# Session: 2025-05-26

**Goal:** Add a retry mechanism to the document processing agent when tool calls fail

---

## Debug: Retry node kept re-running from the start of the graph, not from the failed node

**Symptom:** When a tool call failed, the agent restarted the entire graph instead of
retrying just the failed step. Looked like an infinite loop in the logs.

**Wrong assumption:** Thought that routing back to a node via a conditional edge would
resume state from that node's last output, the way a try/except block would.

**Root cause:** LangGraph doesn't have a "retry from here" concept. Routing to a node
always runs that node fresh. The state it receives is whatever is currently in the graph
state — if nothing clears the error flag, the graph just loops.

**Fix:** Added an `error_count` field to state. The retry node increments it and clears
the tool output before routing back. Added a conditional edge that routes to `END` after
3 retries.

**Takeaway:** LangGraph nodes are stateless functions — they don't remember previous
invocations. If you need retry behaviour, you have to build it explicitly into state.

---

## Built: Retry subgraph with exponential backoff

Implemented a small retry wrapper that lives between the tool node and the next processing
step. It reads `error_count` from state, waits `2^error_count` seconds (via a sleep node),
then re-routes. Kept it as a subgraph so it can be reused across different tool nodes
without duplicating the conditional logic.

---

## Summary

**What I learned today:**
- LangGraph nodes are pure functions over state — no implicit memory of previous runs
- Retry logic requires explicit state fields (`error_count`, `last_error`) and deliberate routing
- Subgraphs are the right abstraction for reusable patterns like retry, fallback, or approval loops

**What surprised me:**
- There's no built-in retry decorator or utility in LangGraph — it's all graph structure

**What I'd do differently:**
- Should have designed the state schema with `error_count` from the start instead of
  bolting it on — the schema shape drives a lot of graph design decisions
